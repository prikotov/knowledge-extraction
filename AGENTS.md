# AGENTS.md — правила работы агента с репозиторием

## Основное

Это репозиторий agent-skill'а [knowledge-extraction](README.md): загрузка материалов
через TasK API, диалог с ними и поиск по фрагментам. Рабочий язык — русский,
коммиты — короткие английские повелительные («Drop site-specific note…»).

## Изменения — только через PR

Прямые пуши в `main` запрещены. Порядок:

1. Ветка от актуального `main`: `task/<краткое-имя>`.
2. Локально перед пушем: `bash -n scripts/*.sh tests/*.sh` и полный прогон
   `tests/*.sh` — все зелёные. Коммитить непрогнанное нельзя.
3. `git push -u origin task/<краткое-имя>` → PR в `main` через `gh pr create`.
4. Дождаться зелёного CI (см. `.github/workflows/ci.yml`: синтаксис + офлайн-тесты).
5. Merge (squash), удалить ветку, синхронизировать локальный `main`
   и зависимые клоны/симлинки рабочим проектов.

Красный CI — не мержить. Мелкие правки тоже идут через PR: история мержей
и есть changelog скилла.

## Изменение скриптов

- Контракт вывода `ingest.sh` (`project_uuid=`, `source_uuid=`, `documents=`,
  `url=`) и машиночитаемость — не ломать: агенты парсят stdout.
- Любое изменение поведения `ingest.sh` / `chat.sh` / `search.sh` сопровождается
  офлайн-тестом (мок-сервер по образцу `tests/*.sh`).
- Формат `.knowledge-extraction.json` менять только обратно-совместимо: старые конфиги
  читаются, миграция — на месте, без потери пользовательских полей.

## Секреты

`.task_token.json` никогда не коммитится и не читается агентом; тесты используют
фиктивные токены и мок-сервер на `127.0.0.1` — никаких обращений к прод-API из CI.
